# pap-log-archive_v4.sh 手动测试步骤

- 环境要求：**Linux 测试机**（脚本依赖 GNU `date -d` 和 `flock`，Git Bash / macOS 不行）
- 所有操作都在沙箱 `/tmp/pap_archive_test` 内进行，不触碰生产目录
- 统一用 `2026-08-19` 作为模拟"今天"，则"昨天" = 2026-08-18
- 归档包名里的主机名以实际 `hostname` 为准，下文用 `$HOST` 代替

---

## 第 0 步：准备沙箱（只做一次）

```bash
export TEST_ROOT=/tmp/pap_archive_test
export HOST=$(hostname)
mkdir -p $TEST_ROOT
# 把 pap-log-archive_v4.sh 上传到 $TEST_ROOT 下，然后生成沙箱版脚本（替换生产路径）：
sed -e "s#/opt/project/PAP/IHUB#$TEST_ROOT/IHUB#g" \
    -e "s#ARCHIVE_DIR=\"/LOG\"#ARCHIVE_DIR=\"$TEST_ROOT/LOG\"#" \
    $TEST_ROOT/pap-log-archive_v4.sh > $TEST_ROOT/archive_test.sh
chmod +x $TEST_ROOT/archive_test.sh
```

确认路径替换成功（应看到所有目录都指向 /tmp/pap_archive_test，**不能残留 /opt 或 /LOG**）：

```bash
grep -n '^LOG_DIR=\|^CONVERT_LOG_DIR=\|^ARCHIVE_DIR=\|^LOCK_FILE=' $TEST_ROOT/archive_test.sh
```

两个常用操作，后面每个用例都会引用：

```bash
# 【重置】清空并重建沙箱目录结构
rm -rf $TEST_ROOT/IHUB $TEST_ROOT/LOG
mkdir -p $TEST_ROOT/IHUB/log/archive $TEST_ROOT/IHUB/logs/convert $TEST_ROOT/LOG

# 【执行】运行脚本（模拟今天=2026-08-19）
bash $TEST_ROOT/archive_test.sh 2026-08-19
```

## 用例 1：基础归档（三类日志 + 今天的文件不动）

**目的**：主流程正确——archive 文件、convert 文件、server 日志进主包；源文件删除；今天的文件保留。

构造现场（先执行【重置】）：

```bash
cd $TEST_ROOT/IHUB/log
echo "all-0818"  > archive/IHUB_ALL.applog.2026-08-18.0.log
echo "info-0818" > archive/IHUB_INFO.applog.2026-08-18.0.log
echo "all-0819"  > archive/IHUB_ALL.applog.2026-08-19.0.log   # 今天的，不应被动
echo "start"     > server_start.log
echo "stop"      > server_stop.log
mkdir -p $TEST_ROOT/IHUB/logs/convert/20260818
echo "req1"      > $TEST_ROOT/IHUB/logs/convert/20260818/req1.log
```

执行【执行】，然后逐项核对：

```bash
ls $TEST_ROOT/LOG/
# □ 存在 $HOST.IHUB-PAP.applog.20260818.tar.gz 和 archive.log

tar -tzf $TEST_ROOT/LOG/$HOST.IHUB-PAP.applog.20260818.tar.gz
# □ 包内 5 项：archive/IHUB_ALL...0818、archive/IHUB_INFO...0818、
#   server_start.log、server_stop.log、convert/20260818/req1.log

ls $TEST_ROOT/IHUB/log/archive/
# □ 只剩 IHUB_ALL.applog.2026-08-19.0.log（今天的）

ls $TEST_ROOT/IHUB/logs/convert/
# □ 20260818 目录已被删除

ls -l $TEST_ROOT/IHUB/log/server_start.log $TEST_ROOT/IHUB/log/server_stop.log
# □ 两个文件存在且大小为 0（被清空而不是删除）

cat $TEST_ROOT/LOG/archive.log
# □ 有一条 archived ...20260818.tar.gz (files: 5)
```

记录主包指纹，用例 2 要用：

```bash
md5sum $TEST_ROOT/LOG/$HOST.IHUB-PAP.applog.20260818.tar.gz
# □ 记下这个 md5 值
```

## 用例 5：多日期积压一次补齐 + 文件名变体

**目的**：模拟 WARN/ERROR 迟到多天的积压；同日期多文件合并；无 applog 段的命名变体也能收；无日期的文件不被误碰。先【重置】：

```bash
cd $TEST_ROOT/IHUB/log/archive
echo a > IHUB_WARN.applog.2026-08-10.0.log
echo b > IHUB_WARN.applog.2026-08-12.0.log
echo c > IHUB_ERROR.applog.2026-08-12.0.log
echo d > IHUB_ALL.2026-08-18.1.log        # 变体：没有 applog 段
echo e > nodateshere.log                  # 无日期
```

执行【执行】，核对：

```bash
ls $TEST_ROOT/LOG/
# □ 生成三个主包：...20260810.tar.gz、...20260812.tar.gz、...20260818.tar.gz

tar -tzf $TEST_ROOT/LOG/$HOST.IHUB-PAP.applog.20260812.tar.gz
# □ WARN 和 ERROR 两个 08-12 文件在同一个包里

tar -tzf $TEST_ROOT/LOG/$HOST.IHUB-PAP.applog.20260818.tar.gz
# □ 含变体文件 archive/IHUB_ALL.2026-08-18.1.log

ls $TEST_ROOT/IHUB/log/archive/
# □ 只剩 nodateshere.log（无日期的文件原样保留）
```

## 用例 6：v3 遗留孤儿救援（复刻生产现场）

**目的**：tar 已存在 + 目录里有孤儿 → v4 首跑把孤儿收进 supp 包，且不动已有主包。先【重置】：

```bash

mkdir -p $TEST_ROOT/placeholder && echo old > $TEST_ROOT/placeholder/old.log
tar -czf $TEST_ROOT/LOG/$HOST.IHUB-PAP.applog.20260812.tar.gz -C $TEST_ROOT/placeholder old.log
md5sum $TEST_ROOT/LOG/$HOST.IHUB-PAP.applog.20260812.tar.gz    # 记下 md5

# 放一个 v3 跳过的孤儿

```

执行【执行】，核对：

```bash

# □ supp1 里是孤儿文件

ls $TEST_ROOT/IHUB/log/archive/
# □ 孤儿已被删除

md5sum $TEST_ROOT/LOG/$HOST.IHUB-PAP.applog.20260812.tar.gz
# □ 与刚才记下的 md5 一致（旧主包未被动过）
```

## 用例 10：并发锁

先【重置】，再造一个待归档文件：

```bash
echo x > $TEST_ROOT/IHUB/log/archive/IHUB_INFO.applog.2026-08-18.0.log

# 在【终端 A】占住锁不放：
exec 9>$TEST_ROOT/IHUB/archive_IHUB-PAP.lock && flock -n 9 && echo "锁已持有"
```

同一个终端 A 里执行【执行】（子进程拿不到锁），核对：

```bash
cat $TEST_ROOT/LOG/archive_error.log
# □ 有一条 "another instance is running, skip."

ls $TEST_ROOT/LOG/*.tar.gz 2>/dev/null
# □ 无归档包生成

# 释放锁后重跑，应正常归档：
exec 9>&-
bash $TEST_ROOT/archive_test.sh 2026-08-19
ls $TEST_ROOT/LOG/*.tar.gz
# □ 主包正常生成
```
